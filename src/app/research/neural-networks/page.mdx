## Executive Summary

This project focused on understanding and optimising neural networks designed for image classification. The speed, accuracy, and computation power of certain networks was benchmarked against optimised counterparts. The benchmarking of networks was conducted using a combination of both the Torch (Lua) and TensorFlow (Python) frameworks.

Using TensorFlow as a foundation a new library called `pyNet` was created for the specific use case of training and constructing networks with complex data structures in Python. This program was also used to create and modify existing datasets to use for training arbitrary networks regardless of their parameters. Additionally this library can be used to create new datasets from existing images and compile them into TensorFlow ready binaries.

The method of optimising these networks is known as quantisation and focused around changing how the activation functions in the convolution layers of these networks evaluate values. By changing the functions to piecewise linear from non-linear functions it was possible to increase the speed at which batches were processed in the network and also increase the training time. Inversely the accuracy of the network suffered as the models used were rudimentary and suffered from several mitigating issues that were eventually fixed in later iterations.

In this project several aspects of the networks were investigated leading to the conclusion that if done correctly, optimisation by quantising a neural network can improve overall performance.

This project provided a way of experimenting with different aspects of the activation functions used in most major deep learning networks currently in operation. It was found, among other things, that changing the activation function to a ternary step will decrease performance if the threshold value is not configured correctly due to underfitting, and the derivative must represent the activation function more precisely to avoid drift when performing gradient descent in backpropagation.

## 2 Theory and Background

### 2.1 Floating Point Numbers

A floating point number is a representation of a real number that is approximated so that it is possible to store on a computer with a finite number of bits. This trade-off of precision compared to range allows the numbers to be stored efficiently. All programming languages have some method for storing and manipulating floats, with most modern representations of single floats comprising 32 bits, with 8 bits used for the exponent. Floating point numbers are ideal for storing precise values of real numbers compared to integers because they support decimal places. Compared to integer precision arithmetic, floating point is more resource intensive on most systems because it requires more CPU operations — in fact, the number of floating point operations per second (FLOPS) is used as a measurement in supercomputing benchmarks.

### 2.4 Deep Learning

Deep learning is a subset of machine learning focusing on methods based around learning specific data representations to solve problems rather than task-specific algorithms that are programmed to solve a problem. A deep learning algorithm can learn how to solve a problem without being specifically programmed how, using either a supervised, partially supervised, or unsupervised algorithm. The great advantage that deep learning algorithms have is that they can perform better than people at specific tasks, and this set of tasks is increasing.

#### 2.4.1 Artificial Neural Networks

An artificial neural network is a computing system inspired by the design of the human brain. In simplistic terms the system is analogous to the operation of neurons and dendrites in an animal brain. In a biological brain, brain cells are connected in a network to perform operations, each brain cell has multiple dendrites that act as connectors which link to other brain cells by their terminals. When enough chemical energy is received by a cell through its dendrites, it fires a signal through its axon which will activate any dendrites connected to its terminal.

In artificial networks these complicated interactions are replaced with mathematical operations. The basic design of a network is to have input nodes connected to other nodes further in the network like a directed, weighted graph. The vertices in the graph act like brain cells while the edges act as dendrites connecting cells. The edges of the graph are weighted with a random unknown variable, by training the network the values for the weights of each edge can be evaluated to give the least amount of error. Each node in a network sums up its inputs and applies an activation function to the value. This new value becomes the output of the node and is passed on to any connected node.

In more recent times, the analogy to biological brains has diminished and is no longer a predominant guide in the field of deep learning. The main reason for this paradigm shift is simply because we do not know enough about how the human brain works to make any more assumptions about solving problems with this system. For further advancements in copying the human brain it would be necessary to monitor the activity of thousands of interconnected neurons simultaneously.

**Layout.** The layout of networks is a continuing topic of research today, there are hundreds of different designs for specific use cases, but all these designs follow a basic outline. Networks consist of an input layer which is connected to several middle layers, which are connected to the output layer. These middle "hidden" layers, named because their hyperparameters are unknown, can have different configurations, ranging from fully-connected to convolution-sparse layers <Cite n={5} />.

**Weights.** The weights in standard neural networks are floating point numbers that can be tuned to lower the output error of the network. When initialised a network's weights are assigned randomly from a distribution. One problem that arises with random assignments is that if a weight's value is zero initially it can be difficult for it to be retuned, to avoid this a bias factor is added to the distribution to mitigate the issue <Cite n={5} />.

**Activation functions.** The activation function of a node defines the output given by a set of inputs. A non-linear activation function allows a network to compute non-trivial solutions to a problem using only a relatively small set of nodes. There are many different activation functions available to use, however most of these functions are similar enough that there is little need for different functions. Using our biological metaphor, the activation functions represent the rate of nerve firing in the brain <Cite n={5} />.

#### 2.4.2 Backpropagation

Backpropagation is a method used in the training of neural networks to calculate and minimise the error that is propagated by the individual weights found across the network. The algorithm requires some sort of loss function to work, this is usually given by the mean squared error of a batch of outputs. The term backwards propagation comes from the fact that the loss function is calculated on the output node and the error is distributed back through the network using a technique similar to the chain rule in calculus <Cite n={9} />.

In this example the change added to each weight is calculated by adding the change in error related to each weight multiplied by the momentum (a known hyperparameter of the training algorithm), and the output value <Cite n={9} />.

#### 2.4.3 Overfitting

Overfitting is a problem encountered in machine learning and other statistical forms of mathematics where the model being analysed to fit a dataset becomes too dependent on the data to make future accurate predictions. This is because if the model fits too perfectly to the data, small errors in the distribution or other sources of noise can cause the model to become sensitive to false positives. This means the model will likely have a higher error rate on unseen data.

This can become a serious problem for neural networks and is a topic of current research. There are several solutions to overfitting, these include having a large dataset, having fewer parameters in a model, and input manipulation <Cite n={9} />.

#### 2.4.4 Quantising

Quantisation covers a lot of different techniques to store numbers and perform calculations in a more compact and efficient way than typical 32-bit floating point numbers. For the purposes of this report quantisation refers to the simplification of activation functions to piecewise linear functions, and the conversion of floating point weights to integer weights <Cite n={[16, 15]} />.

CUDA is a parallel computing platform based around Nvidia GPU chipsets. It provides a way for developers to create software that can efficiently use GPUs in computers for general purpose processing. CUDA is used for a variety of deep learning solutions as much of the maths needed for deep learning algorithms can be easily computed using the parallel processing power of a graphics card.

#### 2.5.2 Torch - Lua

Torch is a mathematical framework written in Lua for the specific use of processing scientific data. Torch can compile code to CUDA instructions and execute operations on both the GPU and CPU. Torch has a wide range of functions that can be used when developing deep learning algorithms. The main branch of Torch was written in Lua, a language specifically created to handle scientific data, however it is not a commonly taught language any more, because of this an alternative version of the framework known as PyTorch was written from the ground up in Python to evolve the framework for a new language.

#### 2.5.3 TensorFlow - Python

TensorFlow is a framework written in Python to handle the creation and manipulation of tensors. In mathematics a tensor is a geometric object that describes a relation between a scalar, vector, matrix, or another tensor. In fact a tensor can be thought of as an extension of a matrix in a higher dimension. The purpose of TensorFlow is to create an easy system to manipulate tensors, this is done in the framework by creating a graph which describes what operations will be performed on each tensor and how the data will flow through the graph — hence the name TensorFlow. After the graph has been defined in Python (or any supported high level language for that matter) the graph is then interpreted into a target language, either C or CUDA and run on the target's processing unit. Because of the ease of use, large developer community, and several other features including TensorBoard, many developers and academics have transitioned to using TensorFlow instead of competing frameworks <Cite n={5} />.

### 2.6 Optimisation via Binary and Ternary Quantisation

As mentioned above the activation functions of a network are what allow networks to solve problems in a relatively small amount of space and time, however by changing how the activation functions work it is possible to increase the speed, and decrease the training time needed to create a working neural network. In this report we will investigate how changing the activation functions to piecewise linear steps modifies the behaviour and characteristics of several different types of networks.

#### 2.6.1 Current Research

Optimisation via quantisation is currently an active field of research in machine learning and there are several efforts currently underway to increase the speed and accuracy of networks using similar techniques to those talked about in this report <Cite n={5} />.

**Binary-Net.** In 2016 a team of researchers in North America and Israel created a network colloquially known as Binary-Net in this report that constrained the activation function outputs and weights to the values of -1 and 1. Their results showed that it is possible to obtain near state-of-the-art results using a binary network while only using a fraction of memory compared to previous networks that had the same results <Cite n={2} />.

**XNOR-Net.** XNOR-Net is another network that was published in 2016 by researchers from the University of Washington. This network expands the field of quantisation by adapting models like VGG, ResNet, and similar binary models so that most of their internal operations are bitwise functions. By converting specific operations such as convolution, and dot products to approximate binary equivalents XNOR-Net again was able to achieve near-state-of-the-art results equivalent to a full precision network while at the same time reducing the footprint needed to compute results by as much as a factor of 58 <Cite n={14} />.

**Ternary-Net.** By expanding on the work of XNOR-Net and Binary-Net researchers again improved the accuracy and compression of a network, this time in China. Academics at the Institute of Applied Math in Beijing were able to run tests on network designs that are similar to the ones mentioned in this report. In their research they created a series of models that used piecewise ternary step functions as the activation functions for convolution layers in their reproductions of VGG-19. Their ternary results showed improvements over their binary models, with increases in accuracy by approximately 5% <Cite n={10} />.

### 3.2 Development and Programming

The algorithm for implementing binary activations was already provided and is quite simple, in Lua all that is needed is to call the library function `Math.sign()` with a tensor as the argument and the function works as expected. To create a ternary step function that can have a variable width it is not possible to execute one operation, instead the fastest way to implement a function like this in Lua follows the algorithm provided below in [Algorithm 1](#alg-1).

The ternary activation function works like a switch statement, if the input value is greater than a specific threshold value then the output is 1. If the input is below the negative of the threshold value then the output is -1. If it is neither the output is 0. Note for the function to work correctly the threshold value must be greater than 0, and less than 1 as this is where most non-linear activation functions converge, this can be seen more clearly in [Figure 2](#fig-2). If the threshold is set improperly then the model will become less accurate than a binary network due to over and under fitting. Optimising the points at which the activation function steps would significantly increase the reliability of the model.

### 4.2 Research and Results

With this new module it is possible to compare the run-times of several different models using the TensorBoard application. The resulting models that were trained using this new method had a consistently smaller file size that resulted from changing the weights from floating point type to integer type.

The answer can be found when changing the threshold value for the step size in ternary net. In initial testing the activation threshold was set to 1, this means that any number in the range of −1 &lt; x &lt; 1 was set to zero. By looking at the comparison of activation functions in [Figure 2](#fig-2) it clearly shows that in that range is where the most changing between levels happens, or putting it another way — where the gradient of the functions has the highest magnitude (this is incredibly important for backpropagation). Because the step in binary net happens when x = 0 there is such a small gap that none of the output values can be zero, as expected.

What's happening here is that too many values are being zeroed in the convolution layers, this means that too much data is being lost by the quantisation effects. Another property of the modified networks is the difference in the rate of change of accuracy. In Figures [6](#fig-6), [7](#fig-7), [8](#fig-8), [9](#fig-9), [10](#fig-10), and [11](#fig-11) it can be seen that binary and ternary net are slower to change and end up lagging behind the original network implementations. This was another anomaly that was not well understood when it was first recorded, with more research it is now better understood why this happened. Both types of networks calculate error by backpropagation using gradient descent. Gradient descent works by changing the weights of a layer by finding out how much error each weight adds to the total. To achieve this the algorithm needs a function that can calculate the derivative of the activation function, an example of this can be seen in [Figure 3](#fig-3). Because in binary and ternary net the activation function is piecewise there is no continuous derivative for these functions. To resolve this the derivative of the step functions was left unchanged from the non-linear counterparts. While this allowed the algorithm to work the inaccuracies between the step functions and their pseudo derivatives meant that small errors grew more rapidly in later iterations, hence why the algorithms plateau at a lower level.

### 5.3 Batch and Filesize Comparisons

Another component that was investigated in this project was how the file size and average batch time changed when the activation functions and weights were modified. In initial testing in Torch and TensorFlow the batch size was seen to reflect how fast a batch could be calculated. The larger the batch the longer it would take both frameworks to process and calculate the values. In the example in [Figure 13](#fig-13) a batch size of 20 was used due to memory constraints.

What was found is that with modified activation functions with input weights being of type `uint8` the speed of the batch processing dropped by varying amounts based on the different networks used. When looking at the file sizes of the networks there was considerable improvement here as well. The most significant improvement occurred with VGG as approximately 100 MB of storage space was saved, this was a saving of approximately 20%.

### 5.4 Analysis

The results of these tests show that quantising any type of network can lead to significant performance improvements — if done correctly. Initially a lot of the testing for this report was done on a trial and error basis. Building off these results it should be possible to revisit some of these configurations in the future and improve and iterate on the decisions made in this report.

## 6 Conclusion

In this project, the behaviour of optimised and non-optimised neural networks was evaluated. This was done by developing and testing several networks in both the Torch and TensorFlow frameworks, with their results combined and analysed to determine how changing the activation functions of convolution layers varies the speed, accuracy, and training time of these networks. The results show that by converting the activation functions from non-linear to linear piecewise functions improves the speed at which a network can be trained and evaluated because each individual batch takes less time to be computed. The analysis also showed that this improvement shrank file sizes by as much as 20% meaning that the models could be more easily transferred and shared to smaller devices. Furthermore the decrease in accuracy and increase in error is possible to minimise by changing some parameters that were used in making this report, such as how the gradient of functions is calculated, and what threshold value should be used for the ternary step activation function.

The module created for this project called `pyNet` will be available on GitHub and should provide a starting point for further investigations into the area of network quantisation. The `pyNet` module can be used to train any neural network that supports the output format specified in the library, it also makes it possible to create a training set from any hierarchical file system and run these datasets on any supported network. This will allow future researchers to quickly iterate on past work and improve performance.

Further areas of improvement for this project lie in how some of the calculations for optimisations are made. If more bitwise operations were supported in Torch and TensorFlow on CUDA devices then the performance of networks could again be increased. In the analysis section it is mentioned that if the quantisation of networks is done correctly then the accuracy of the system should remain state-of-the-art, however, in the testing done this was not fully achieved and the accuracy of the networks remained 5%–10% below what other researchers have reported, this could be addressed with more attention in a later endeavour.

With the mobile and IoT sectors of the market continuing to expand and with companies like Intel <Cite n={12} /> and Apple focusing on releasing more powerful chipsets aimed at machine learning applications, the future of optimisation relating to neural networks will be an important topic that will require up to date tools and theories to satisfy demand.
