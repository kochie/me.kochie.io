# OpenGraph Image Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the static `/images/AirplaneMaker.jpg` OpenGraph image with a dynamically generated 1200×630 card rendering the hero quote, served from `app/opengraph-image.tsx`.

**Architecture:** Single-file Next.js App Router route at `src/app/opengraph-image.tsx` returning a `next/og` `ImageResponse`. Two static-instance TTF fonts (Fraunces Italic 400, JetBrains Mono Medium 500) sit alongside the route and are loaded via `import.meta.url`. Manual `openGraph.images` and `twitter.images` arrays in `src/app/page.tsx` are removed because Next auto-wires the meta tags from the file convention.

**Tech Stack:** Next.js 16 (App Router), `next/og` (Satori-backed), Fraunces Italic + JetBrains Mono Medium TTFs from Google Fonts, pnpm.

**Spec:** `docs/superpowers/specs/2026-04-30-og-image-design.md`

---

## File Structure

| File | Responsibility |
|---|---|
| `src/app/opengraph-image.tsx` *(new)* | Route handler — returns `ImageResponse` with the rendered card |
| `src/app/Fraunces-Italic.woff` *(new)* | Display font (static italic 400 instance), bundled via `import.meta.url` |
| `src/app/JetBrainsMono-Medium.woff` *(new)* | Mono font (static normal 500 instance), bundled via `import.meta.url` |
| `src/app/page.tsx` *(modified)* | Drop redundant `openGraph.images` and `twitter.images` arrays |

**Note on font format:** `.woff` rather than `.ttf` because the cleanest static-instance source (the `@fontsource` packages on jsDelivr) only ships WOFF/WOFF2. Satori accepts WOFF natively. The Google Fonts repo only ships variable-axis files for these families, no static-instance TTFs.

No automated tests — the route renders a static image with no runtime data, and the spec marks visual-regression testing out of scope. Verification is browser-based.

## Task 2: Create the OG renderer

**Files:**
- Create: `src/app/opengraph-image.tsx`

- [ ] **Step 1: Create `src/app/opengraph-image.tsx` with the renderer**

  ```tsx
  import { ImageResponse } from 'next/og'
  import { readFile } from 'node:fs/promises'
  import { join } from 'node:path'

  export const alt =
    'Robert Koch — I build things, write the code for them, & run from the resulting explosion.'

  export const size = { width: 1200, height: 630 }

  export const contentType = 'image/png'

  const PAPER = '#faf6ec'
  const INK = '#171311'
  const WHEAT = '#d9b67a'

  export default async function OpengraphImage() {
    const [fraunces, mono] = await Promise.all([
      readFile(join(process.cwd(), 'src/app/Fraunces-Italic.woff')),
      readFile(join(process.cwd(), 'src/app/JetBrainsMono-Medium.woff')),
    ])

    return new ImageResponse(
      (
        <div
          style={{
            width: '100%',
            height: '100%',
            background: PAPER,
            color: INK,
            padding: '41px 84px',
            display: 'flex',
            flexDirection: 'column',
            justifyContent: 'space-between',
          }}
        >
          {/* Eyebrow */}
          <div
            style={{
              display: 'flex',
              alignItems: 'center',
              gap: 17,
              fontFamily: 'JetBrains Mono',
              fontSize: 20,
              letterSpacing: '0.22em',
              textTransform: 'uppercase',
            }}
          >
            <div
              style={{
                width: 60,
                height: 1,
                background: INK,
                opacity: 0.55,
              }}
            />
            <span>Robert Koch · Melbourne</span>
          </div>

          {/* Hook */}
          <div
            style={{
              display: 'flex',
              flexDirection: 'column',
              fontFamily: 'Fraunces',
              fontStyle: 'italic',
              fontSize: 92,
              lineHeight: 0.95,
              letterSpacing: '-0.02em',
            }}
          >
            <span>I build things,</span>
            <span>write the code for them,</span>
            <span>{'& run from the'}</span>
            <span style={{ color: WHEAT }}>resulting explosion.</span>
          </div>

          {/* Meta */}
          <div
            style={{
              display: 'flex',
              justifyContent: 'space-between',
              fontFamily: 'JetBrains Mono',
              fontSize: 20,
              letterSpacing: '0.22em',
              textTransform: 'uppercase',
              opacity: 0.78,
            }}
          >
            <span>Engineer · Speaker · Guitarist</span>
            <span>me.kochie.io</span>
          </div>
        </div>
      ),
      {
        ...size,
        fonts: [
          {
            name: 'Fraunces',
            data: fraunces,
            style: 'italic',
            weight: 400,
          },
          {
            name: 'JetBrains Mono',
            data: mono,
            style: 'normal',
            weight: 500,
          },
        ],
      },
    )
  }
  ```

  **Why each thing is there:**
  - `alt`, `size`, `contentType` are special exports Next reads to populate `<meta>` tags and the route's response headers.
  - Fonts are loaded with `readFile(join(process.cwd(), …))` — the canonical pattern from the Next.js 16 OG-image docs. (An earlier draft used `fetch(new URL(…, import.meta.url))`, which fails at runtime in Next 16.2.4 + Node 25.)
  - `Promise.all` parallelizes both font reads; they're independent.
  - `padding: '41px 84px'` matches the spec's 6.5%/7% margins (630 × 0.065, 1200 × 0.07).
  - Each flex container has explicit `display: 'flex'` — Satori warns otherwise.
  - The `&` is wrapped in `{'& run from the'}` rather than left as raw `&` to avoid any JSX parser quibbles.
  - No `runtime` export — Next 16 picks Fluid Compute by default, which is what we want.

- [ ] **Step 5: View-source on the homepage to confirm meta wiring**

  Visit `http://localhost:3000/` in a browser, then View Source (Cmd+U on macOS).

  Search the markup for `og:image`. Expected output:
  - Exactly one `<meta property="og:image" content="..."/>` tag
  - The URL ends in `/opengraph-image?<some-hash>` or `/opengraph-image.png`, **not** `/images/AirplaneMaker.jpg`

  Search for `twitter:image`. Twitter inherits from `og:image` when no `twitter:image` meta is set, so it's fine if `twitter:image` is absent — most viewers will still get a card. If you'd rather be explicit, that's a follow-up (add `app/twitter-image.tsx` re-exporting the same renderer).

## Out of Scope (per spec)

- Per-talk OG cards (`app/talks/[slug]/opengraph-image.tsx`) — separate spec/plan
- Variable-font axes (Satori doesn't support them well; visual difference invisible at 92px)
- Dark variant — single fixed asset, light was chosen
- Removing `/public/images/AirplaneMaker.jpg` from disk — leave it; may be referenced elsewhere
- A separate `twitter-image.tsx` — Twitter inherits from `og:image`, single file is sufficient
- Automated visual-regression testing — UI is static, hand-verification covers it
